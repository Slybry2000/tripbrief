# The backend

Convex owns the whole product: the operator network, the client briefs, every
private response link, every proposal, the inbound mail, the provider quotas, and
the hosting of the built frontend.

| File | What it owns |
|---|---|
| `schema.ts` | Every table and the shared validators the seed and the tests reuse. Read this first. |
| `seedData.ts` | Generated by `scripts/build-seed.mjs` from the demo's fictional network: ten operators, one capability record each. Invented data. |
| `network.ts` | The operator network: the matcher's read, both kinds of private link (a standing capability link and a request link), the one write path an operator has (its capability record), per-workspace seeding, adding an operator by hand or from research, and removing one that has never quoted. |
| `briefs.ts` | The client brief and its workflow: create, save, choose the customer-approved locations, shortlist operators (which mints each request link), record the decision, delete the brief and everything it produced. |
| `proposals.ts` | Structured proposals: an operator submitting through its own link, an advisor recording one that arrived by email, and the OpenAI drafting action that returns a review draft and never writes. |
| `research.ts` | Firecrawl searching published websites for operators, and the candidate records it produces. |
| `mailboxes.ts` | The workspace's small pool of mailboxes (a free mail plan allows three in total, so briefs share them), the display-name and inbox parsing, and the provider probe. |
| `outbound.ts` | The only thing in the app that sends: one named operator, one address a human typed, one link. |
| `replies.ts` | Inbound mail. The mailbox says which workspace it belongs to; the **thread** says which request it answers, with the sender's address as a labelled fallback. Mail that matches nothing is kept unfiled rather than dropped. Also the webhook registration probe. |
| `integrationLimits.ts` | Per-workspace and app-wide quotas for AI drafting, research, sending and inboxes. |
| `openai.ts` | The single place the Responses API is called; store-free and schema-constrained. |
| `http.ts` | `/incoming/agentmail` (shared-secret-guarded) and the static hosting of the frontend. |

## Conventions worth keeping

- Identity always comes from the session. No function takes an owner argument.
- Optional columns are written with a neutral value (`""`, `0`) rather than
  omitted, so a revision can clear an earlier claim without ambiguity.
- Reads return an explicit projection, never a spread of the stored document, so
  a column added later cannot start leaking through an existing endpoint.
- Anything a browser can write is bounded before it is stored (`cleanCapability`,
  `cleanProposal`, `cleanBrief`).
- Two actions (`research.search`, `proposals.draftFromReply`) annotate their
  handler's return type on purpose: they call `api`/`internal`, whose types import
  this module, and without the annotation TypeScript reports a circular inference
  instead of a real error.

## Commands

```text
npx convex dev                       # push functions and watch
npx convex run network:seed '{"owner":"<account id>"}'   # seed one workspace (idempotent)
npx convex run --prod replies:registerWebhook
```

A workspace seeds itself on first sign-in (`network.ensureWorkspace`), so the CLI
seed is only for setting up a named account without a browser.
